# Evidence Dossier: Harness Execution Contracts & Why Autonomous Agents Stop
Compiled 2026-11-15. Labels: **[impl-verified]** = read directly from official docs/source this session; **[doc-claim]** = vendor doc text, not independently executed; **[community]** = non-vendor report; **[inference]** = my synthesis. `[single-source]` = only one source found; two-source claims left untagged.

## Slice A — Harness execution contracts

### OpenAI Codex CLI (github.com/openai/codex)
- `codex exec` = non-interactive mode; progress on stderr, final agent message on stdout; `--json` makes stdout a JSONL event stream (`thread.started`, `turn.started`, `turn.completed`, `turn.failed`, `item.*`, `error`); `--output-schema` enforces a JSON Schema final answer; `-o` writes last message; `--ephemeral` skips persisting session rollout files (rollouts otherwise default to disk). **[impl-verified]** [verified: https://developers.openai.com/codex/non-interactive-mode]
- Resume: `codex exec resume --last` or `codex exec resume <SESSION_ID>` continues a rollout. Default sandbox read-only; `--sandbox workspace-write`/`danger-full-access` for unattended writes; `--full-auto` removed; `CODEX_API_KEY` per-invocation auth; git repo required unless `--skip-git-repo-check`. **[impl-verified]** [same URL]
- Cancellation & state: `codex app-server` (JSON-RPC 2.0 over stdio JSONL; ws experimental) exposes `thread/resume`, `thread/fork`, `turn/interrupt` (turn ends `status:"interrupted"`), `turn/steer`, `thread/status/changed` with runtime status `notLoaded|idle|systemError|active(activeFlags:[waitingOnApproval])`; thread history is a persisted JSONL rollout with pagination. **[impl-verified]** [verified: https://developers.openai.com/codex/app-server]
- Limit signaling is first-class: `account/rateLimits/read`, `account/rateLimits/updated` notification, `rateLimitReachedType`, earned `account/rateLimitResetCredit/consume`, plus server-initiated owner notifications for depleted credits/`usage_limit`. **[impl-verified]** [same URL, grep of full doc]
- SDKs: TS `@openai/codex-sdk` `startThread/resumeThread(threadId)`; Python `openai-codex` `thread_start/thread_resume/thread_fork`, `include_turns=False`, `threadSource` label. `codex mcp-server` removed → app-server. **[impl-verified]** [verified: https://developers.openai.com/codex/codex-sdk]
- Gaps: no documented hang/watchdog signal — finished vs hung must be inferred from `turn.completed` presence vs event silence (**[inference]**); cross-harness handoff is migration-only (`externalAgentConfig/detect|import` moves configs/skills/AGENTS.md/sessions from other agents, not live interop). **[impl-verified]** [app-server URL]

### Claude Code (Anthropic)
- `claude -p` headless; exit 0/non-zero; `--output-format json` (result, session_id, total_cost_usd), `stream-json` (NDJSON; `system/init` carries version-agnostic `capabilities` list for feature detection; final `result` message), `--json-schema` → `structured_output`. **[impl-verified]** [verified: https://code.claude.com/docs/en/headless]
- Resume: `--continue`, `--resume <session_id>`, or `--resume <absolute path to .jsonl transcript>`; works from any directory on the machine. **[impl-verified]** [same]
- Cancellation: SIGTERM → exit 143, turn left unfinished, kills running Bash process tree, runs SessionEnd hooks; SIGINT or Agent SDK `interrupt()` ends the turn; `CLAUDE_CODE_RESUME_INTERRUPTED_TURN=1` resumes the interrupted turn. **[impl-verified]** [same]
- Unattended permissions: `--permission-mode auto|dontAsk|acceptEdits`, `--permission-prompts none` ("nobody available to answer"), `--bare` recommended for scripts (skips hooks/MCP/CLAUDE.md; "will become the default for `-p`"). **[impl-verified]** [same]
- Limit detection: `system/api_retry` events carry typed errors incl. `rate_limit`, `authentication_failed`, `billing_error`, `overloaded`. **[impl-verified]** [same]. Limits officially = 5-hour rolling session + weekly caps **[impl-verified]** [verified: https://support.claude.com/en/articles/11647753-how-do-usage-and-length-limits-work]; 5-hour limits doubled May 6 2026 [verified: https://www.anthropic.com/news/higher-limits-spacex]; per-window (5h/7d) utilization+reset headers visible in rate-limit responses, `rate_limits` statusline field since v2.1.80 **[community]** [single-source: https://github.com/anthropics/claude-code/issues/29579, comment 2026-09-28]; `StopFailure` hook with `rate_limit|overloaded|billing_error` matchers **[community]** [single-source: https://www.morphllm.com/claude-code-usage-limits, 2026]
- Documented fragility: a `-p` run can **exit 0 before a backgrounded subagent command finishes**; the 10-minute idle wait ceiling **drops partial results**; auto-backgrounded MCP call results are lost at exit. **[impl-verified]** [headless URL]

### OpenCode (canonical repo now github.com/anomalyco/opencode)
- Repo verification: docs footer "©2026 Anomaly", GitHub links to `anomalyco/opencode` (sst/opencode era docs remain online as V1). **[impl-verified]** [verified: https://opencode.ai/docs/api/]
- Headless: `opencode run` for scripts/CI; shared per-user background server owns sessions/config/permissions/tool execution (`--standalone`/`--server` override). **[impl-verified]** [verified: https://opencode.ai/docs/cli/]
- V1 server: `opencode serve` HTTP + OpenAPI 3.1 + generated SDK; `/session/:id/abort`, `/prompt_async`, `/session/status`, SSE `/event`. **[impl-verified]** [verified: https://opencode.ai/docs/server/]
- V2 HttpApi (170 ops): `/api/session/{id}/prompt`, `/interrupt`, `/experimental/session/{id}/wait` (block until idle), fork, compact, export/import, permission ask/reply, `/api/event`; V2Event union includes `session.execution.started|succeeded|failed|interrupted`, `session.idle`, `session.retry.scheduled`, `session.compaction.started|ended|failed`, `session.usage.recorded`, `permission.asked`. Usage limits endpoint: `/api/experimental/usage/limits`. Scheduler outcomes model `fired|late|skipped|expired|failed` — missed/late events are surfaced, not dropped. **[impl-verified]** [verified: https://opencode.ai/docs/api/]
- Gaps: several supervisor-relevant routes are labeled "experimental" (wait, usage limits, session export/import) — API-stability risk (**[inference]** from doc labels); no documented hang watchdog beyond `session.idle` semantics.

### Pi coding agent (Mario Zechner / badlogic → now Earendil Inc.)
- Canonical repo: `earendil-works/pi` (ex `badlogic/pi-mono`); Pi 1.0 shipped 2026-10-01 with "Pi Durable". **[impl-verified]** [verified: https://pi.dev/]
- Four modes: interactive, print/JSON (`pi -p`, `--mode json`), **RPC** (JSONL records over stdin/stdout, long-lived subprocess), SDK. No permission popups by design ("run in a container"). **[impl-verified]** [same]
- RPC protocol: commands `prompt`, `steer`, `follow_up`, `abort`, `compact`, `set_auto_retry`/`abort_retry`, `fork`, `clone`, `switch_session`, `get_session_stats`; event stream distinguishes `agent_end` (one run ended) from **`agent_settled` ("Pi will not continue automatically")** — retries, compaction, steering can follow `agent_end`; prompt response carries `disposition` (`started`/`handled`); orderly shutdown via stdin EOF/SIGTERM; clients "must handle child-process startup failures, unexpected exits, cancellation, and their own deadlines." **[impl-verified]** [verified: https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/rpc.md]
- Sessions: tree-structured, all branches in one file; fork/clone/branch via RPC. **[impl-verified]** [pi.dev]
- The vendor's own framing: Pi the coding agent is "driven by one person… If the process dies, you look at what happened and tell it to continue" — unattended durability was **out of scope** and spun into experimental **Pi Durable** (task checkpoints, crash resume, exactly-once `requestId` submissions, background compaction, handoff notes). **[impl-verified]** [verified: https://earendil.com/posts/pi-durable/, 2026-10-01]
- Gap: no first-class usage-limit protocol; provider failures/retries surface as generic events; `set_auto_retry` exists but limit-vs-error classification is the client's job. **[inference]** [rpc.md]

### Common minimal contract — plausibility (**[inference]** from the above)
Plausible as a thin driver: all four give (1) headless spawn, (2) NDJSON/JSONL event stream, (3) persisted session + resume-by-id, (4) explicit cancel, (5) some limit signal. Vendor convergence is visible (Codex app-server ≈ Pi RPC ≈ OpenCode server: long-lived JSON protocol + thread/session + interrupt + status events). Non-portable residue: limit semantics (per-vendor windows/credits), completion subtleties (`agent_settled` vs `turn.completed` vs `result`), permission models, session formats. A contract of {spawn, events, settle, resume(id), cancel, limit?, deadline?} fits; full session-content interop does not exist anywhere and is migration-only at best.

## Slice B — What actually stops autonomous agents (solvability: INFRA = ordinary infrastructure suffices; AGENT-DOMAIN = needs agent-specific logic; UNSOLVED)
1. **Usage/rate-limit lockouts** — Claude: 5-hour rolling + weekly caps, hard lockout until reset [verified: https://support.claude.com/en/articles/11647753]; Codex: typed `rateLimitReachedType` + reset credits [app-server]. Detection is solved; waiting out windows / pooling subscriptions is plumbing. → **INFRA** (pooling report: ghuntley.com, Oct 2026 [single-source, community]).
2. **Auth expiry / credential flapping** — subscription-type flip silently drained API credits until re-login; `/status` showed a different counter than the limiter used [community: claude-code#29579, May–Sep 2026]; typed `authentication_failed` retry events exist [official]. → **INFRA** (token refresh, re-auth), with residual mystery-state risk.
3. **Context exhaustion / compaction failure** — quality clips at ~147–152k tokens; "the number of compilation errors was so large that it filled Claude's context window" [community: https://ghuntley.com/ralph/, 2025-07-14]; OpenCode models `session.compaction.failed` [official]. Auto-compaction exists in all four; pathological fills still break runs; Ralph's fixes (fresh context per loop, subagents, one item per loop) are agent-domain techniques. → **AGENT-DOMAIN + INFRA hybrid**.
4. **Premature "task complete" declarations** — overnight run: "as much as Claude may claim things are 100% perfectly implemented… demos don't work yet"; agents settled into self-congratulatory TODO updates; one agent `pkill`ed its own process when stuck [community: https://github.com/repomirrorhq/repomirror/blob/main/repomirror.md, 2025-08-25]; placeholder-implementation bias documented by Huntley (same URL as #3). No harness signals this; requires verification back-pressure (tests/typecheck) wired into prompts. → **AGENT-DOMAIN / UNSOLVED** by infrastructure alone.
5. **Non-progress loops & broken-codebase wakeups** — "you will wake up to a broken code base… is it easier to `git reset --hard`"; Ralph has "three states: under baked, baked, or baked with unspecified latent behaviours" [community: ghuntley.com/ralph]. → **AGENT-DOMAIN** (detect via externally-run tests; recovery is human/policy judgment).
6. **Process crash / lost orchestration state** — Pi vendor: process death = human recovery, motivating Pi Durable's checkpoints [verified: pi-durable post]; Ralph's while-loop + git-committed `fix_plan.md`/`TODO.md`/`AGENT.md` as crash-tolerant state [community]; repomirror's "commit+push after every file edit, scratchpad in .agent/" [community]. Session files survive (all four); semantic plan state must live outside the agent's memory. → **INFRA for process liveness; AGENT-DOMAIN for state design**.
7. **Silent idle exit / false success** — vendor-documented: `claude -p` can exit **0** before a backgrounded command finishes; 10-min idle ceiling drops partial results; MCP background results lost [verified: code.claude.com/docs/en/headless]. Exit-code checking alone is unsafe. → **INFRA-detectable** (must verify effects, not exit codes).
8. **Missed scheduler events** — OpenCode explicitly models schedule outcomes `late|skipped|expired|failed` [verified: opencode.ai/docs/api] — evidence the class is real and handled only in one harness. → **INFRA**.
9. **Conflicting concurrent agents** — Beads exists for exactly this: atomic claim (`bd update --claim`), hash IDs "prevent merge collisions in multi-agent/multi-branch workflows" [verified: beads README]; Yegge built Gas Town to orchestrate 20–30 parallel agents on top [community: michaellivs.com]. → **INFRA** (leases/claims/worktrees).
10. **Hanging tools / stuck turns** — no harness ships a hang watchdog; Codex offers only a `systemError` thread status; every RPC doc pushes deadlines onto the client [official docs, all four]. → **INFRA** (timeout-on-event-silence is the supervisor's job) but currently **undocumented/unhandled by vendors**.
11. **Incomplete side effects after successful exit** — Pi Durable's replay-safety design ("a deploy interrupted by a crash is reported to the model, never repeated") acknowledges rerun-unsafety is intrinsic [verified: pi-durable]; repomirror mitigated by commit+push-per-edit [community]. → **AGENT-DOMAIN / UNSOLVED** in general; mitigate by making side effects idempotent or externally verifiable.

## Beads note
- Canonical repo **moved**: `steveyegge/beads` → `gastownhall/beads` (GitHub redirect observed this session; 28.8k stars; "Distributed graph issue tracker for AI agents, powered by Dolt"). **[impl-verified]** [verified: https://github.com/gastownhall/beads, README Nov 2026]
- What it guarantees: dependency graph with `bd ready` auto-detection of unblocked work; atomic claims; hash-based IDs (`bd-a1b2`) preventing merge collisions across agents/branches; durable memory via `bd prime`/`bd remember` injected into agent context; Dolt-backed sync (`bd dolt push/pull`), embedded or server mode. **[impl-verified]** [same]
- **Correction to the "JSONL memory" framing:** `.beads/issues.jsonl` is explicitly "an export for viewers and interchange, **not the source of truth or a backup**" — the Dolt database is the source of truth. **[impl-verified]** [same]
- **Not an executor — verified:** the CLI's entire surface is create/claim/close/depend/remember; no command launches or supervises an agent. Workflow assumes an external harness reads `AGENTS.md` and does the work. Execution/orchestration is a separate product ("he built Beads to give coding agents memory. Then he built Gas Town to orchestrate 20-30 agents in parallel" [community: https://michaellivs.com/blog/claude-code-tasks-dependencies]). A supervisor still needs its own loop; Beads only supplies shared task state and claims.
